# Proposal Message Schema

## Purpose

This schema defines the output structure for internal-review proposal message drafts generated by Task 008: Proposal Message Generator.

The output is for internal review only. It must not imply that a message has been sent, approved for sending, or automatically delivered to a buyer.

This schema does not implement code, CSV generation, Markdown output generation, XLSX generation, email sending, messaging automation, scraping, live web research, automatic web search, APIs, browser automation, crawlers, buyer enrichment, credit checks, or external data collection.

## Output Fields

The proposal message output must include these fields exactly, in this order:

1. `message_id`
2. `buyer_id`
3. `company_name`
4. `country`
5. `language`
6. `priority_tier`
7. `approval_block`
8. `message_status`
9. `message_type`
10. `subject_or_opening`
11. `message_body`
12. `recommended_brands`
13. `excluded_brands`
14. `compliance_notes`
15. `required_internal_review`
16. `next_action`
17. `generated_at`

## Field Definitions

| Field | Meaning | Required | Format | Allowed values | Example | Notes |
|---|---|---:|---|---|---|---|
| `message_id` | Unique identifier for the generated proposal message draft. | Required | Text ID, preferably `MSG-0001` style. | Unique value per output record. | `MSG-0001` | Must not be reused within the same output. |
| `buyer_id` | Buyer lead identifier from buyer master and scored buyer CSV files. | Required | Existing buyer ID. | Must match `buyer_id` from buyer master and scored buyer CSV. | `BUYER-0001` | Must not be invented or changed. |
| `company_name` | Buyer company name from buyer master CSV. | Required | UTF-8 text. | Free text from input only. | `Shanghai Sample Beauty Trade` | Must not be invented. Do not include unnecessary contact-person data. |
| `country` | Buyer country from buyer master CSV. | Required | UTF-8 text. | Free text from input only. | `China` | Used for internal context and language planning. |
| `language` | Message draft language. | Required | Controlled text. | `Korean`, `English`, `Chinese` | `Chinese` | Unsupported or unknown buyer languages should be mapped to `English` by default in future generator logic. |
| `priority_tier` | Internal follow-up priority tier from scored buyer CSV. | Required | Controlled text. | `A`, `B`, `C`, `Hold` | `A` | Must not be described as buyer authenticity, creditworthiness, payment ability, or purchase probability. |
| `approval_block` | Whether approval rules block buyer-facing proposal readiness. | Required | Boolean text. | `true`, `false` | `true` | If `true`, buyer-facing proposal copy must not be generated. |
| `message_status` | Internal status of the generated draft. | Required | Controlled text. | `draft_ready_for_internal_review`, `blocked_approval_required`, `needs_more_buyer_info`, `needs_moq_confirmation`, `needs_payment_risk_review` | `draft_ready_for_internal_review` | This status does not mean the message is approved to send. |
| `message_type` | Type of proposal message draft or internal guidance. | Required | Controlled text. | `first_contact`, `follow_up`, `quotation_intro`, `product_category_intro`, `approval_review_required`, `low_priority_nurture` | `first_contact` | `approval_block=true` must use `approval_review_required`. |
| `subject_or_opening` | Subject line or opening sentence for the draft. | Required | UTF-8 text. | Free text. | `Internal review draft: K-beauty supply introduction` | Must be conservative, suitable for internal review, and must not imply the message has been sent. |
| `message_body` | Internal-review draft message body or internal guidance. | Required | UTF-8 text. | Free text. | `This is an internal-review draft only...` | If `approval_block=true`, this must contain internal approval guidance only, not buyer-facing proposal copy. |
| `recommended_brands` | Brands allowed to appear in the draft recommendation. | Optional | Semicolon-separated UTF-8 text or blank. | Brands with `proposal_allowed=true` and `approval_required=false`, unless explicit approval exists. | `아누아; 토리든` | Must not include `메디큐브` unless explicit approval is recorded. Must not invent brand availability. |
| `excluded_brands` | Brands excluded due to approval-required or proposal-blocked rules. | Optional | Semicolon-separated UTF-8 text or blank. | Free text from input or brand approval reference. | `메디큐브` | If `메디큐브` appears in `interested_brands` without approval, it should appear here. |
| `compliance_notes` | Internal review cautions and compliance notes. | Required | UTF-8 text. | Free text. | `내부 검토용 초안입니다. 가격/재고/효능 표현은 검증 필요.` | Must include cautions such as internal review only, approval-required brand check, no price/stock verification, cosmetics claim review, and localization review where relevant. |
| `required_internal_review` | Whether internal review is required before any external use. | Required | Boolean text. | `true`, `false` | `true` | Should be `true` when approval is blocked, MOQ/payment risk/buyer information is uncertain, or localization review is needed. |
| `next_action` | Practical internal next step. | Required | UTF-8 text. | Free text. | `내부 브랜드 승인 여부 확인` | Must not trigger external sending. See Next Action Examples. |
| `generated_at` | Date when the draft was generated. | Required | ISO date. | `YYYY-MM-DD` | `2026-06-08` | Use the local generation date. |

## Message Status Rules

Allowed `message_status` values:

- `draft_ready_for_internal_review`
- `blocked_approval_required`
- `needs_more_buyer_info`
- `needs_moq_confirmation`
- `needs_payment_risk_review`

Rules:

- `approval_block=true` must use `blocked_approval_required` or internal approval guidance only.
- `moq_fit=no` or `moq_fit=unknown` should use `needs_moq_confirmation` unless the message is only an internal follow-up note.
- `payment_risk=high` should use `needs_payment_risk_review`.
- Missing required buyer information should use `needs_more_buyer_info`.
- `draft_ready_for_internal_review` means the draft can be reviewed internally. It does not mean it can be sent externally.

## Message Type Rules

Allowed `message_type` values:

- `first_contact`
- `follow_up`
- `quotation_intro`
- `product_category_intro`
- `approval_review_required`
- `low_priority_nurture`

Rules:

- `approval_block=true` must use `approval_review_required`.
- Low-priority or `Hold` buyers should not receive aggressive proposal drafts.
- `quotation_intro` must not include invented price, stock, inventory, expiry date, official certification, exclusive rights, contract terms, or guaranteed availability.
- `product_category_intro` may describe broad product categories only and must avoid unsupported cosmetic efficacy, medical, clinical, dermatological, or functional claims.

## Brand Approval Rules

- `data/brands_master.csv` should be used as the local approval reference where available.
- `proposal_allowed=false` brands must not appear in `recommended_brands`.
- `approval_required=true` brands must not appear in `recommended_brands` unless explicit approval is recorded.
- `메디큐브` must remain approval-required unless explicit approval is provided.
- If `interested_brands` includes `메디큐브` without approval, `메디큐브` should appear in `excluded_brands`.
- `approval_block=true` rows must not contain external proposal copy.
- A high `priority_tier` or high buyer score must not override `approval_block`.
- Official English brand names must not be guessed when `brand_en` is blank.

## Business Rules

- All generated messages are internal-review drafts only.
- The schema must not imply automatic sending.
- `approval_block=true` rows must not contain external proposal copy.
- A high `priority_tier` must not override `approval_block`.
- `메디큐브` must remain approval-required unless explicit approval is provided.
- `proposal_allowed=false` brands must not appear in `recommended_brands`.
- Do not include unnecessary contact fields such as `contact_email`, `contact_phone`, `wechat_id`, or `whatsapp`.
- Do not invent price, stock, inventory, expiry date, certification, exclusive rights, or contract terms.
- Do not make cosmetic efficacy, medical, clinical, dermatological, or functional claims unless provided and verified.
- MOQ 100+ and delivery lead time 20-30 days may be mentioned only as general business terms.
- Buyer score must not be described as buyer authenticity, creditworthiness, payment ability, or purchase probability.
- Korean, English, and Chinese text must be preserved.

## Compliance Notes Guidance

`compliance_notes` should mention relevant review cautions, such as:

- internal review only
- approval-required brand check
- no price or stock verification
- cosmetics claims require review
- localization or translation review needed
- buyer is unverified
- source is manually provided only
- MOQ or payment risk requires confirmation

## Next Action Examples

Recommended `next_action` examples:

- `내부 브랜드 승인 여부 확인`
- `MOQ 충족 가능 여부 확인`
- `가격/재고/유통기한 확인 후 견적 준비`
- `중국어 표현 현지화 검토`
- `결제 조건 및 리스크 내부 검토`
- `승인 가능 브랜드 기준으로 메시지 초안 재검토`

These examples are internal actions only. They must not trigger external sending.

## Validation Requirements

Generated proposal message outputs must be validated for:

- Required output fields exist.
- `buyer_id` matches input buyer data.
- `message_id` is unique.
- `message_status` uses allowed values.
- `message_type` uses allowed values.
- `priority_tier` uses `A`, `B`, `C`, or `Hold`.
- `approval_block` uses `true` or `false`.
- `required_internal_review` uses `true` or `false`.
- `approval_block=true` rows do not contain buyer-facing proposal copy.
- `메디큐브` is not in `recommended_brands` unless explicit approval exists.
- `proposal_allowed=false` brands are not in `recommended_brands`.
- `excluded_brands` includes approval-required interested brands where applicable.
- `message_body` does not contain fake price, stock, inventory, expiry date, certification, exclusive rights, efficacy, clinical, medical, or guaranteed-performance claims.
- No unnecessary contact data is exposed.
- Internal review disclaimer exists.
- Korean, English, and Chinese text is preserved.
- No email sending, messaging automation, external sending workflow, scraping, live web research, automatic web search, APIs, browser automation, crawlers, buyer enrichment, credit checks, or external data collection is implied.
